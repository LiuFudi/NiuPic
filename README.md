# NiuPic · 牛图库

> 为飞牛 fnOS 设计的轻量、快速、稳定的图像素材检索浏览应用。
> 支持数十万级别图片流畅浏览，非侵入式设计，100% 开源免费。

## 权限设置（装完必做）

NiuPic 和其他飞牛应用一样，**默认看不到任何用户文件夹**。能访问哪些目录，由你在应用中心手动授权：

```
应用中心 → 已安装 → NiuPic → 应用设置 → 可访问文件夹 → 添加目录（权限选「读写」）
```

授权完成后回到 NiuPic，点「+ 添加新素材库」：

- 上面授权过的目录会**直接列出来**，点一下选中即可，不需要输入任何路径
- 列表里会标出状态：`只读`、`已添加`、`路径不存在`、`已有索引`
- 素材库名称会跟着选中的文件夹自动填好，可以自己改
- 管理员改完授权后，点列表右上角的刷新按钮就能看到最新结果

> 为什么必须从「可访问文件夹」里选而不是自己输路径？因为飞牛给应用的是一套 ACL，
> 没授权的路径应用**根本读不到**。让应用自己列清单，就不会再出现「路径写对了但没权限」这种坑。
> 条目上的 `存储空间1/...` 是飞牛的语义路径，下面一行是真实路径，两者都会显示。

## 升级 / 更新

**从 2.1.2 起，更新版本不会再动你的配置**（素材库列表、访问密码、主题色都会保留）。
之前每次更新都等于重装，是因为卸载脚本会删配置文件，现在已经修掉：

- 卸载默认**保留**数据，只有你在卸载向导里选「全部删除」才会清理
- 每次保存配置都会留一份 `config.json.bak`，安装时发现主配置不见了会自动恢复

> **2.5.5 起配置放在 `etc/`**（`/vol{N}/@appconf/niupic/`，飞牛卸载时不删），
> 不再是 `@appdata`。首次启动会自动把旧位置那份**复制**过去（旧文件留着兜底）。
> 下面那条 2.1.x 的历史备份命令里的 `@appdata` 是**当时**的位置，现在照着做要换成 `@appconf`。

> **从 2.1.1 升到 2.1.2 会丢一次配置**：执行删除的是已经装在机器上的 2.1.1。
> 想连这一次也不丢，装之前先备份一下，新版会自动恢复：
>
> ```bash
> cp /vol1/@appdata/niupic/config.json /vol1/@appdata/niupic/config.json.bak
> ```

## 从 FlyPic 迁移

NiuPic 沿用了 FlyPic 的索引格式，**旧素材库不用重新扫描、不用重建缩略图**。

假设你有素材库 `/vol1/1000/Photos`（卷号以你的 NAS 为准，下面统一写 `/vol1`）：

```bash
# 1. 安装 NiuPic · 牛图库（应用中心 → 手动安装 → niupic_2.6.0_x86.fpk）
# 2. 在 NAS 上以 root 执行迁移脚本（把 .flypic 就地改成 .niupic）
node /vol1/@appcenter/niupic/server/scripts/migrate-flypic-dir.js /vol1/1000/Photos
#    有多个素材库就一次传多个路径
# 3. 打开 NiuPic → 应用设置里授权该目录 → 添加素材库 → 从列表里选中同一路径
#    会提示 "Library created with existing index"，图片和缩略图立刻可用
```

迁移脚本做两件事：重命名目录、把数据库里 `thumbnail_path` 的 `.flypic/` 前缀改成 `.niupic/`。
两步都是就地操作，秒级完成。不做迁移直接重新扫描也可以，只是大库会花不少时间重建缩略图。

> ⚠️ `appname` 从 `flypic` 改成了 `niupic`，所以 NiuPic 对 fnOS 来说是一个**新应用**：
> 素材库列表、访问密码、主题这些存在 `/vol1/@appdata/` 里的配置不会自动继承，需要重新设置一次。
> 但素材库里的索引（`.niupic/`）和图片本身都不受影响。

## 功能

- 🖼️ **双击全屏查看器** —— 滚轮以光标为锚点缩放、双击在「适应窗口 / 100%」间切换、拖拽平移、
  `[` `]` 旋转、`I` 文件信息、`F` 全屏、空格幻灯片、`←/→` 切换，工具栏自动隐藏
- 📚 **素材库管理** —— 多素材库、任意层级目录，首页即全部图片；
  添加素材库时**直接列出飞牛已授权的「可访问文件夹」**，不用手输路径
- 🎨 **主题色自定义** —— 12 种预设色 + 色轮（色相/饱和度/明度），就放在筛选卡片右侧；换色全站立即生效并记住
- 🔍 **智能搜索 + 筛选/排除** —— 搜索框在顶栏正中；筛选条件可在「只显示 / 排除」两种模式间切换；
  格式选项**只列出当前文件夹里真实存在的**（带条数），按 **图片 → 视频 → 其他** 分组，
  组头可一键选中/取消整组；文件大小是**两个把手的区间滑块**（默认占两端 = 不限），
  刻度显示在滑条下面（< 1M / 1-5 / … / 100+），拖到哪一段就筛哪一段
- 🔄 **扫描库文件** —— 两个维度自由组合：**范围**（当前库 / 任意一个库 / 全部库）× **方式**
  （增量扫描 / 全量扫描）。**全量扫描会跳过没改动过的文件**（只重读变化过的、补缺失的缩略图），
  大库在机械硬盘上不再是"每次半小时"；另有**「修复文件夹结构」**：只按数据库重建文件夹列表和
  每层张数，**不读磁盘**，几秒钟完成。扫描结束会明确报出「找到 N 个文件」，
  **0 个文件会直接提示去查权限/路径**（不再只说"扫描完成"）
- 🧱 **瀑布流布局** —— 顶栏滑块**直接决定图片高度**（视频/PSD 一样生效）；行间距可调；可开启「按文件夹分隔」，不同文件夹之间画横线隔开；拖动滑块时画面不会跳
- ↕️ **灵活排序** —— 任意层级可用，14 个排序字段（时间 / 文件名 / 大小 / 分辨率 / 宽高比 /
  类型 / 评分 / 收藏 / 所在文件夹 / 随机），文件名走自然排序，偏好跨刷新记住；
  顶栏**一个按钮**（按钮上写着「筛选 / 排序 / 主题色」）开两张卡片：**排序卡置顶**，
  下面是**筛选卡**——桌面端筛选条件和主题色按 **6 : 4** 横向排开（主题色是右边一栏，用紧凑版），
  手机端自动变成上下排；卡片画在图片区里、宽度正好是图片区宽度 ——
  只挤图片区，左右侧栏纹丝不动，内容也不会横向溢出
- 🧮 **筛选在后端生效** —— 筛的是整个素材库而不是"已经加载的那一页"，
  翻页之后的图片同样受筛选影响，界面上的总数也是筛选后的真实总数
- ⚡ **大库友好** —— 虚拟滚动、分页加载、缩略图延迟生成、内存监控与自动清理
- 🎨 **现代界面** —— 固定行高瀑布流、亮色 / 暗色主题、响应式
- 🔒 **访问控制** —— 密码 + JWT，防暴力破解
- 🗂️ **文件操作** —— 重命名、移动、删除（走回收站）、评分、导出；
  详情里的路径**按飞牛的真实写法（正斜杠）显示**，路径正下方两个按钮分别复制 Win / Linux 写法
- 📷 **相机 RAW 支持** —— DNG / CR2 / CR3 / NEF / ARW / RW2 / ORF / RAF 等：从 RAW 里
  抠出内嵌的 JPEG 预览，**有缩略图、宽高也是真的**（不再是一律 640×480 的占位）
- 🎬 **视频封面** —— 用 ffmpeg 抽帧（按 ffprobe 的时长挑时间点，**不到 1 秒的短片也有封面**），
  宽高来自 ffprobe，比例不会错
- 🔌 **实时同步** —— Socket.IO 推送扫描进度与文件变化

## 开发

```bash
# 前端
cd frontend && pnpm install --ignore-workspace && pnpm run dev

# 后端
cd backend && npm install && npm run dev
```

## 打包 fpk

```bash
node scripts/build-fpk.js          # 需要 fnpack 在 PATH 里
# 产物: dist/niupic_<version>_x86.fpk
```
